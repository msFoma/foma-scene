# Work in the current Blender session

1. Discover the currently connected Blender MCP tools and their parameter schemas. Call `inspect_scene` with its default selection scope. Establish the file, scene, session, frame, active object, material sharing and `background` flag. Reuse the reported IDs within that session. For browsing a large collection use paginated `detail="summary"`. Before editing a result, fetch that object with `detail="edit"` to get its layers and fresh write guard.
2. Capture the baseline with `observe`. In GUI Blender use `view.mode=viewport` to see the current editor. For a repeatable comparison choose named cameras and use the same camera, frame and render settings before and after. Keep both capture job IDs. If `verify_edit` is available, check the visible scope without rendering again. Choose image regions based on the baseline and supply `min_changed_pixels` where the edit should appear and `max_changed_pixels` where the result should stay stable. Include an opposite view when a projection might bleed. Inspect the overlay for failures. Keep geometric and material measurements alongside this pixel evidence.
3. For an edit, send the newest scoped `revision_token` or `scene_token` and a unique `job_id`. Retain the exact request. Refresh inspection after any stale revision or selection response. For a timeout or reconnect, ask `job_status` with the same ID. To retrieve a completed result replay the identical operation with that ID. If its status is unknown after restart, inspect the scene for the expected effect before retrying. `cancel_job` cancels queued work. A running Blender operator must finish.
4. Use `apply_layer` for a masked image on the active mesh slot. Size and signed depth use millimetres. For a +Z projection, U and V are local X and Y, and the depth interval selects the front surface. Use the alpha of the source image for the mask and request roughness only where needed. To shift the same layer along local X, use `move_layer` with its existing `layer_id`. Use `update_layer` for opacity or finish refinements. Check physical width, layer count, neighboring objects sharing the source, large enough close-up and opposite side.
5. Use `list_addons` and `enable_addon` for a compatible installed module. Confirm registration from its returned operator list. For `import_svg`, verify editable curve IDs. For `bool_difference`, confirm two distinct selected meshes, the active body, the cutter, its token, and the modifier index. Inspect the cut from each side and confirm that it evaluates while remaining editable. For `node_texture`, open an unpinned Object Shader Editor, target the correct material slot and shader node, and check the resulting node types. Report any failed poll and its actual editor.
6. For a reference, agree on named orthographic cameras, an alpha mask per view, named landmarks with normalized top-left coordinates and a tolerance. Register them with `set_reference_spec`. Use `compare_reference` to inspect overlays, silhouette IoU and landmark errors. Depth requires an annotated side view and expected depth. Use `finalize_asset` to run the checks again on current geometry. Judge lighting, finish and fine detail using actual camera or viewport images.
7. Use `checkpoint` to save an explicit scene copy before a series of edits. Use `rollback` for recent guarded MCP edits. Inspect the output and capture the post-rollback state. For delivery, use `verify_glb` on a collection with its mesh hierarchy. Check imported geometry, transforms, material channels and the effects listed as needing baking. Report measurements, received images, the Blender mode and remaining visual decisions.
